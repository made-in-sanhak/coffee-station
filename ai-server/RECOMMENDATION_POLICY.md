# 추천 구현 원칙

사용자와 합의한 구현 기준. 이후 추천 기능 변경 시 이 문서를 따른다.

1. 현재 명시적 요청 > 가입 취향/과거 행동. 가격 상한·거리·종류 등 필수 조건부터 적용한다.
2. 필수 조건은 점수로 상쇄하거나 자동 완화하지 않는다. 정보 없음은 충족이 아니다.
3. 초기에는 가격순/거리순 등 명시적 정렬을 Python으로 처리한다. Gemini는 요청 해석과 도구 선택을 담당한다.
4. 추후 목적 35%, 취향 25%, 거리 20%, 가격 15%, 리뷰 5%를 실험용 출발점으로 검증한다.
   고정 정답이 아니며 현재 요청에 따라 조정한다. 지금은 가중치 점수를 구현하지 않는다.
5. 매장 환경 리뷰와 메뉴 맛 평가를 분리한다. 클릭을 좋아요로 확정하지 않는다.
6. 리뷰 수가 적으면 평균 쪽으로 보정하고, 신규 사용자/매장을 데이터 부재만으로 불리하게 하지 않는다.
7. 판매 매장·메뉴·옵션 단위로 평가하고, 추후 결과의 매장 다양성을 고려한다.
8. 알레르기/디카페인/영업 상태는 검증 가능한 데이터와 필터가 마련된 뒤 지원한다. 지원하지 않는 조건을 충족했다고 표시하지 않는다.

현재 HTTP API는 확정 조건을 별도로 받는다. 자유 문장의 모든 조건을 자동 확정하거나
취향·리뷰 점수·대화 세션을 제공하는 단계가 아니다.
