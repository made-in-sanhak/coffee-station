# 행신 자료 기반 개발 순서

이번 사용자 요청으로 제공된 행신 자료의 테스트 사용을 승인받았다.
다른 실제 데이터/리뷰의 사용 승인을 의미하지 않는다. Gemini/Git 작업은 하지 않았다.

## 이번 완료

1. 로컬 Docker MySQL 시작, 별도 coffee_station_haengsin_test DB 생성.
2. 매장 8개/가격 옵션 57개 적재. 기존 업무 테이블은 변경하지 않음.
3. 앱 DB 계정에 이 테스트 DB의 SELECT 권한만 추가.
4. 읽기 전용 search_prices 구현: 메뉴명, 가격 상한, HOT/ICE, 사이즈, 매장 코드.
5. 매장별 최저가 옵션 비교(사이즈/온도/상품명/가격 근거 보존).
6. 실제 데이터용 노트북을 행신 DB 테스트로 최신화하고 실제 실행 검증.

검증: ICE/4000원 이하 아메리카노 12옵션, 카페라떼 6옵션.
가격 상한 포함, 0원 검색 빈 결과, unverified 2행, 좌표 전부 누락 확인.
출처 없음/unverified는 기본 검색에서 제외하나 나머지가 검증된 현재 판매가격이라는 뜻은 아니다.
배달/픽업/브랜드/과거 사진 가격이 혼재한다. 동일 용량 단가 비교도 아직 아니다.
결과는 가격 비교용 후보이며 영업·판매 가능·재고를 확정하지 않는다.

## 이어서 가능한 작업

7. Express/Python에 별도 가격 비교 API 추가(운영 추천과 구분).
8. 앱의 메뉴/온도/사이즈 필터와 출처·미검증 표시 연결.
9. 가격 비교 결과에서 매장별 최저 옵션 선택 흐름 검증.

## 자료가 더 필요한 작업

10. 주소·위도/경도·카카오 장소 ID 확보 및 내부 cafe_id 매핑.
11. 카카오 지도 마커 표시와 가격 비교 후보 연결.
12. 가격 검증일·판매 상태·옵션 정규화 후 운영 추천 Repository로 전환.
13. 거리 추천, 리뷰/취향 개인화는 해당 데이터 확보 후 진행.

노트북: ai-server/notebooks/real_data_ready.ipynb.
ai-server/.venv 커널, Docker 실행 후 RUN_HAENGSIN_TEST=True로 테스트한다.
저장된 노트북 기본값은 False이며 결과 출력은 저장하지 않았다.
모의 데이터 노트북은 계속 별도로 유지한다. 서버 추천 기본 설정도 변경하지 않았다.
