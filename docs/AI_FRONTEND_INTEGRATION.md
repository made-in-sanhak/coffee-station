# 프런트·지도 통합 준비 — 10단계

사용자 확인: 프런트 담당자와 아직 미합의이므로 연결 준비까지만 진행한다. 기존 로그인·지도·탭·추천 화면 진입점은 변경하지 않았다.

## 현재 준비한 것

`frontend/src/api/recommendationMap.ts`는 추천의 cafe.id를 명시적 CafeStoreLink(cafeId 문자열, storeId 숫자)로 기존 Store에 대응한다. 매핑이 유일하고 기존 Store 좌표가 유효할 때만 READY와 해당 Store를 반환한다. ID 숫자 변환이나 좌표/가격/평점 생성은 하지 않는다.

모의 결과는 MOCK_RESULT, 매핑 없음/중복은 MAPPING_MISSING/AMBIGUOUS, 지도 조회 결과에 매장 없음은 STORE_MISSING, 좌표 오류는 INVALID_COORDINATES로 반환한다. 현재 실제 추천 경로가 미연결이므로 실제 앱에서 READY가 검증된 것은 아니다. 테스트의 is_mock=false는 합성 fixture이며 실제 매장 데이터가 아니다.

기존 Store는 선택 메뉴의 가격 정보를 포함한다. 이 어댑터의 선택은 매장 위치만 가리키며 추천 메뉴·옵션 가격과 지도 카드 가격이 같다는 보장은 없다. 최종 UI는 cafe_id/menu_id/offer_id와 현재 지도 메뉴 필터를 함께 다뤄야 한다.

## 확인된 차이와 합의 목록

| 항목 | 현재 차이 | 합의할 내용 |
|---|---|---|
| ID | 추천 문자열 cafe.id, 지도 숫자 Store.id | 동일 DB ID인지 별도 매핑인지, Kakao 장소 ID 구분 |
| 메뉴 | COFFEE/LATTE/TEA/ETC 대 AMERICANO/LATTE/DECAF | 표준 menu_id와 category 분리. COFFEE→AMERICANO 자동 매핑 금지 |
| 좌표 | 추천 응답에는 실제 매장 좌표 없음 | 상세 조회 또는 지도 응답 재사용, 조회 범위 밖 매장 처리 |
| 추천 진입 | 기존 탭은 준비 중 알림, 독립 실습 화면 존재 | #9와 화면 하나로 통합할 위치·책임·파일 규칙 |
| 거리 입력 | 백엔드 합성 거리 지원, 프런트 기존 타입은 가격 전용 | 위치 권한·지도 중심/사용자 위치 선택·반경 입력·재준비 UX |
| 응답 표시 | 프런트가 mock 응답만 허용 | 실제 모드 전환 시 명시적 데이터 표기와 검증 |
| 오류 | apiFetch가 HTTP 상태를 문구로 변환 | 429 Retry-After, 제안 만료·연결 실패·재시도 상태 보존 |
| 인증 | 프런트 토큰 store는 있으나 현 backend 인증 미연결 | 서버가 검증한 사용자 계약 후 소유권 모듈 연결 |

## 합의 이후 구현·검증 순서

1. 담당자와 위 계약 및 요청/응답 fixture 확정. 매핑 출처는 서버/DB로 정하며 앱 하드코딩을 실제 매장 매핑으로 사용하지 않는다.
2. 모의/실제 표시 및 메뉴 옵션 식별을 포함해 프런트 API 타입을 통합한다. 기존 독립 실습 화면을 중복 추가하지 않는다.
3. 추천 결과 선택→해당 매장 조회→마커 강조·카드 표시. 매핑/좌표 부족 시 연결 불가 안내, 다른 매장으로 대체하지 않는다.
4. 원문·위치·모드 변경 시 제안 무효화, 최종 조건 명시적 확인, 중복 버튼·로딩·취소·빈 결과·만료·429 검증.
5. 에뮬레이터에서 PC 서버 주소 10.0.2.2:8080, 서버 바인딩·연결 상태 확인. 추천 API는 기본 mock 유지. 실제 Gemini/DB/지도 API 테스트는 해당 승인·설정 후 실행.
6. 기존 로그인·지도·탭 동작과 권한 거부·화면 복귀·조회 범위 밖 매장을 수동 검증하고 캡처 기록.

## 실행 결과와 제한

frontend에서 `npx tsc --noEmit` 성공. `npm test -- --runInBand`는 초기 샌드박스 캐시 EPERM 후 로컬 재실행하여 5개 suite/9개 테스트 통과(신규 어댑터 2개 포함). 실제 외부 API/DB 호출 없음.

지도 컴포넌트에 어댑터를 연결하지 않았고 에뮬레이터·Kakao 화면 검증은 미실행이다. 10단계 전체 통합 완료가 아니다. 담당자 합의 전 관련 화면·네비게이션 구조 변경은 보류한다. 11단계 실제 Gemini 평가는 별도 호출 승인/예산이 있어야 실행한다.
