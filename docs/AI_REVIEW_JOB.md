# 리뷰 Agent 작업 — 8단계 모의 구현

`app/review_job.py`는 snapshot 관찰→모델 결정→허용 행동→검증·저장 결과 관찰을 반복한다. 모델 행동은 analyze(opinions)와 refresh뿐이며 임의 SQL·저장 위치·외부 URL은 받지 않는다. 저장은 코드가 Repository의 인용/버전 검증을 통과한 경우에만 한다.

MockReviewModel은 조용/시끄 문자열에 따른 규칙 기반 모의 모델이다. 실제 LLM Agent 품질을 검증한 것이 아니다. 고정 처리 부분은 snapshot 조회·publish 검증이며 모델이 선택하는 부분은 분석 제출/재조회다. 오류 관찰에는 코드만 전달하고 원문이나 내부 사고 과정을 trace에 기록하지 않는다.

기본 최대 3회 모델 결정, 10초 경과 검사. READY/BUSY/TIMEOUT/LIMIT_REACHED/FAILED를 반환한다. 잘못된 인용은 제한 내 수정할 수 있고 입력 변경은 새 snapshot을 가져온 뒤 재분석한다. 동일 runner의 같은 매장 중복 실행을 차단하며 종료 시 점유를 해제한다.

시간 검사는 호출 전후의 협력적 제한이다. 멈춘 모델 호출을 강제 중단하지 못한다. 실제 제공자 연결 시 요청 타임아웃/취소 및 공유 작업 lease가 필요하다. 현재 lock은 프로세스·runner 로컬이고 내구성 있는 작업 큐/다중 worker 중복 방지/장애 후 회수는 미구현이다. 이 상태를 운영 작업 스케줄러로 사용하지 않는다.

검증: 새 Agent 테스트 4개와 저장소 회귀 3개 통과. 정상 상반 의견, 가짜 인용→refresh→수정, 분석 중 리뷰 변경, 잘못된 행동의 호출 한도, 시간 초과, 모델 오류, 로컬 중복 거절을 확인했다. 모의 노트북에 실행 셀을 추가하고 해당 새 셀만 직접 실행해 READY와 두 의견을 확인했다. 노트북 전체 실행은 미실행이다.

후속: 실제 Agent 제공자 어댑터(별도 승인된 평가), 영속 작업 상태/재시도/분산 lease, 실제 DB Repository·Express 조회, 개인정보 최소화/인용 길이·입력 총량 제한, 운영 관측 및 의미 품질 평가가 필요하다. 기존 파일 export/API에는 자동 연결하지 않았다. 다음 9단계는 이 모의 의견을 추천 특징으로 집계하는 계약부터 진행할 수 있다.
