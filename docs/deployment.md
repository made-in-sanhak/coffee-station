# 배포 안내

> 현재 배포 제약과 운영 활성화 전 점검 문서. 추천 MVP 개발 순서는 [문서 안내](README.md) 참조.

기준: 2026-11-10. 현재 운영 준비 완료가 아니다. [실시간 추천](ai-recommendation.md), [리뷰 작업](ai-review-analysis.md), [미완료 계획](ai-development-plan.md)을 함께 확인한다.

## 현재 구성

[운영 Compose](../infra/docker-compose.prod.yml)는 Express backend만 빌드·실행하고 NODE_ENV=production을 지정한다. 상시 Python HTTP 서비스나 backend의 Python 의존은 없다. production 추천·모의 리뷰 조회는 503 차단된다. 이는 의존성 오류 해결이나 기능 배포 완료가 아니라 의도적 운영 보호다.

[로컬 Compose](../infra/docker-compose.yml)는 필요한 작업에서만 쓰는 MySQL이다. 모의 추천 테스트에는 실행할 필요가 없다. 기존 DB/볼륨을 임의 삭제하지 않는다. backend Dockerfile은 production 환경으로 설정되지만 이번 문서 정리에서 이미지 빌드·실행을 검증하지 않았다.

## 환경과 실행

.env.example의 기본 추출 모드는 mock이다. Gemini를 활성화하려면 키·모델 설정이 필요하지만 실서비스 활성화와 별개다. 비밀값은 환경으로 주입하고 로그·이미지·앱에 넣지 않는다. NODE_ENV 누락은 development, HOST 기본값은 0.0.0.0이므로 운영에서 production 지정과 차단을 확인해야 한다.

Python은 ai-jobs의 유한 리뷰 작업을 실행하는 구조가 목표다. 현재 운영 작업 이미지/스케줄러/실제 DB 저장은 없다. 초기 제안은 같은 호스트의 일회성 작업 컨테이너이며 별도 작업 환경은 필요 시 검토한다. 확정·배포된 결정이 아니다. 로컬 export는 실제 Agent/운영 파이프라인을 대체하지 않는다.

## 운영 활성화 전 확인

1. 인증된 사용자·제안 소유권과 키 분리/교체, 직접 검색 포함 접근 제한.
2. 실제 공유 할당량·동시 lease·요청/제공자/ALB 시간 예산·유한 재시도·취소. 프록시 헤더를 무조건 신뢰하지 않도록 trust proxy 범위 지정.
3. 실제 스키마·검증 가격/좌표·읽기 전용 권한·연결 풀·RDS CA/TLS 인증서 검증. 인증서 검증을 끄지 않는다.
4. 리뷰 변경/삭제 무효화·현재 revision 조회·작업 큐/실패 재처리/중복 방지·모니터링/알림. 원문/위치/토큰 대신 요청 ID·시간·상태·호출 수 기록.
5. 깨끗한 이미지 시작·실제 두 서버·재시작·저장소 장애 검증, 프런트 담당자 합의 및 에뮬레이터 검증. 수행하지 않은 항목은 미검증으로 표시.
6. 스키마/응답 버전 호환, 기능 비활성화·이전 버전 복구 절차. 복구를 이유로 기존 데이터를 삭제하지 않는다.

환경·제안서·구성도에는 현재 모의 경로와 목표 DB/분석 작업 경로를 구분해 표시한다. Git·배포 실행은 사용자가 요청한 범위에서만 진행한다.
