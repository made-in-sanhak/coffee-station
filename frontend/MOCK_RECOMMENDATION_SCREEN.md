# 추천 입력 → 조건 확인 → 결과

기본 화면은 RecommendationScreen이다. 상단 버튼으로 기존 모의 리뷰 화면을 열 수 있다.
기본 local 모드는 임시 메뉴 6개를 사용하며 네트워크 호출이 없다.
지원 예시: '4천 원 이하 커피를 저렴한 순으로 추천해줘.'
미등록 문장은 추가 확인으로 표시하고 확인 버튼을 제공하지 않는다.

1. 요청 입력/예시 불러오기 → 조건 추출
2. 원문 근거 확인 → 예산(빈 값은 상한 없음)/종류 수정 → 확인·추천
3. 메뉴·가격·가상 매장 표시. 4000원 3개, 3500원 2개, 2999원은 질문/빈 결과.

현재 정렬은 가격순, 최대 20개다. 위치 입력/거리순 화면은 후속 단계다.
원문 수정이나 실행 모드 변경 시 이전 제안/결과를 버린다. 요청 중 중복 실행을 막는다.
서버 모드의 확인 요청은 1회성이므로 완료/실패 후 새로 추출해야 한다.

에뮬레이터 준비 후 '모의 서버로 전환'을 선택할 수 있다.
Python: EXTRACTION_MODE=mock, RECOMMENDATION_MODE=direct,
AGENT_REPOSITORY=mock(또는 격리된 데모 DB만 사용하는 mysql-demo).
실제 DB를 선택하는 mysql 모드는 사용하지 않는다. 내부 토큰은 두 서버에서 동일하게 설정한다.
Android 에뮬레이터 주소는 기존 client.ts의 http://10.0.2.2:8080.
Express가 PC의 접근 가능한 인터페이스에서 수신해야 한다.
서버 메뉴는 로컬 메뉴와 다를 수 있다. 서버는 전체 모의 카탈로그 또는 데모 SQL을 사용한다.
앱에서는 모의 추출/모의 메뉴 응답만 허용한다. 모드 표시 검사는 실제 DB 접근을 막는 서버 권한을 대신하지 않는다.

이번 검증은 로컬 모의 데이터 타입/린트/자동 테스트다.
에뮬레이터·실제 HTTP 화면 연결·키보드 레이아웃 검증은 기기 준비 후 진행한다.
실제 데이터/Gemini/Git 작업은 수행하지 않았다.
